## 2. Перечень технических проблем

### A. Архитектура и структура (высокий приоритет)

| # | Severity | Проблема | Где |
|---|:---:|---|---|
| A1 | 🟥 | **Нет единого источника кода** — 3 копии одного лендинга, код дрейфует (разные имена классов: `.branch-card` / `.branch-card` / `.branches-*`, разные CSS-переменные). | `ttt/`, `../`, `../testsite/` |
| A2 | 🟥 | Файл `index.css` на самом деле содержит HTML — вводит в заблуждение редактор/сборщики/людей. | `../index.css` |
| A3 | 🟥 | **Монолит**: весь CSS и JS зашиты в один HTML. Нет разделения ресурсов → нет кеширования, нет минификации, нет повторного использования. | `ttt/index.html` |
| A4 | 🟨 | Отсутствует build-процесс/инструментарий (Vite/Gulp) для сб по-этапной разработки и прод-сборки. | проект в целом |

### B. HTML и семантика

| # | Severity | Проблема | Где |
|---|:---:|---|---|
| B1 | 🟥 | Нет `<main>`; контент завернут в `section` без `aria-labelledby`; навигация — `<nav>` с голыми `<a>` без `<ul>/<li>`. Невалидная/нестабильная семантика. | `ttt/index.html` header |
| B2 | 🟨 | Ветки/залы/аренда: внутри `<article>`-карточек `<div>`-структура используется для «иконок», SVG без `aria-hidden="true"` в части мест; декоративные стрелки `→` без `aria-hidden`. | branches/halls/rental |
| B3 | 🟨 | Заглушки контактов: `+7 (812) 000-00-00`, `hello@hardwork.spb` (несуществующий TLD `.spb`), `mailto:hello@hardwork.spb`, `href="#"` — нет реальных данных. | hero/cta/footer |
| B4 | 🟨 | Нет `defer`/`type="module"` у скрипта; бургер-меню без полноценного `aria-expanded`/`aria-controls` в части копий. | `ttt/index.html` |

### C. Доступность (a11y)

| # | Severity | Проблема |
|---|:---:|---|
| C1 | 🟥 | Нет skip-link («Перейти к контенту»). |
| C2 | 🟨 | Нет стилей `:focus-visible` для клавиатуры (фокус незаметен на тёмном фоне). |
| C3 | 🟨 | Контраст `--muted` (#a0a0ab) на `--bg` (#0d0d0f) может не проходить WCAG AA для текста мелкого кегля. |
| C4 | 🟨 | Декоративные SVG/стрелки без `aria-hidden` — озвучиваются скринридерами. |
| C5 | 🟨 | Цвет используется как единственный сигнал интерактивности (hover) — нужен border/underline/фона. |

### D. SEO и метаданные

| # | Severity | Проблема |
|---|:---:|---|
| D1 | 🟥 | Нет structured data (JSON-LD) — подходящие типы `DanceStudio`/`LocalBusiness` + филиалы с гео/графиком. |
| D2 | 🟨 | Нет Open Graph / Twitter Card, нет favicon, нет `canonical`. |
| D3 | 🟨 | Мета description есть, но нет ключевых страниц под каждый филиал (одностраничник). |
| D4 | 🟨 | Нет реальных контактов/адресов (карта, телефоны, email) для локального SEO. |

### E. Производительность

| # | Severity | Проблема |
|---|:---:|---|
| E1 | 🟨 | Тяжёлые `filter: blur(40px)` + большие радиальные градиенты в hero/cta — нагрузка на GPU, фризы на слабых устройствах; нет fallback для `prefers-reduced-motion` на декоративные градиенты. |
| E2 | 🟨 | Инлайн-подход исключает кеширование CSS/JS между страницами; при расширении сайта стили будут дублироваться. |
| E3 | 🟨 | `section { padding: 100px 0 }` без адаптивного уменьшения; нет `content-visibility`/`contain` для секций вне вьюпорта. |
| E4 | 🟢 | Шрифт не подключается (системный стек) — ок, но нет font-display/hinting управления для будущих web-fonts. |

## 3. Архитектурный план оптимизации

### Этап 0 — Консолидация источника (устраняет A1, A2)
- Признать `ttt/index.html` **единственным источником правды**.
- Удалить/перенести в архив дубли: `../index.css` и `../testsite/index.html` (после согласования с пользователем — не трогать чужое в десктопе без подтверждения).
- Зафиксировать единый набор классов и CSS-переменных.

### Этап 1 — Разделение на слои (устраняет A3, E2)
Целевая структура проекта:

```
ttt/
├── index.html              ← разметка + ссылки на ресурсы
├── assets/
│   ├── css/
│   │   ├── tokens.css      ← CSS-переменные/токены дизайн-системы
│   │   ├── base.css        ← reset, типографика, кнопки
│   │   ├── layout.css      ← header/hero/branches/halls/rental/cta/footer
│   │   ├── responsive.css  ← медиазапросы
│   │   └── main.css        ← @import или сборка единого бандла
│   ├── js/
│   │   └── main.js         ← бургер-меню, якоря, defer-подключение
│   ├── img/                ← SVG-иконки/изображения залов, favicon
```

### Этап 2 — Валидация и семантика (устраняет B1, B2)
- Обернуть контент в `<main id="main">` + skip-link.
- Навигацию обернуть в `<ul>/<li>`, дать `aria-current`.
- Все декоративные SVG и стрелки — `aria-hidden="true"`, иконки-смысловые — с `<title>`/`role="img"`.
- Исправить незакрытые/несоответствующие теги (аудит провалидера W3C).

### Этап 3 — Доступность (устраняет C1–C5)
- Skip-link, `:focus-visible` с акцентной обводкой.
- Пересчитать контраст `--muted` (поднять до #b3b3bd), проверить WCAG AA.
- Индикатор интерактивности: underline/border при hover/focus.

### Этап 4 — SEO (устраняет D1–D4)
- JSON-LD (JSON-LD `DanceStudio` + филиалы: адрес, геолокация, метро, часы, телефон).
- Favicon (SVG), Open Graph + Twitter Card, `canonical`.
- Реальные контакты (телефон/email/адреса) вместо заглушек.

### Этап 5 — Производительность (устраняет E1, E3)
- Ограничить `blur()` (уменьшить радиус/убрать на мобильных), добавить `@media (prefers-reduced-motion: reduce)` отключение декора.
- `content-visibility: auto; contain-intrinsic-size` для секций вне экрана.
- Минификация CSS/JS на прод-сборке.

### Этап 6 — Проверка качества
- Валидатор W3C, Lighthouse (Performance/A11y/SEO), чек-лист клавиатуры, тест на реальных телефонах.
